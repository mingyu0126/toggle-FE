# No Code Before Design

## When This Applies

- any new feature
- any user-visible UX change
- any API or DTO contract change
- any non-trivial bugfix or refactor

## Mandatory Rules

- Start with design/brainstorming before feature code.
- Create a short but explicit artifact in `handoff/` or `docs/superpowers/specs/`.
- Get a human approval checkpoint before implementation.

## Forbidden

- going straight from user request to implementation
- inventing behavior while coding
- treating "simple" as a reason to skip design

## Expected Outputs

- approved design/spec
- explicit scope and success criteria

## Exceptions

Only trivial typo-only, comment-only, or document-only changes may skip this rule.
