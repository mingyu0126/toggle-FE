# PRD: Favorite Store

## 1. Overview
- 회원이 마음에 드는 매장을 즐겨찾기할 수 있는 기능이다.
- 사용자는 다시 방문하고 싶은 매장을 빠르게 모아볼 수 있다.
- 대상 역할은 `Member`이며, `Guest`는 탐색만 가능하고 즐겨찾기 저장은 불가능하다.

## 2. Problem Statement
- 현재 Toggle의 핵심 탐색 가치는 "지금 갈 수 있는 매장을 빨리 찾는 것"인데, 마음에 드는 매장을 다시 찾는 개인화 기능이 없으면 반복 사용성이 떨어진다.
- 사용자가 다시 같은 매장을 찾을 때 검색이나 지도 탐색을 반복해야 하므로 MVP 개인화 가치가 약해진다.

## 3. Goal
- 회원은 매장 상세, 카드, 리스트 등에서 매장을 즐겨찾기할 수 있다.
- 회원은 저장한 매장 목록을 한 곳에서 볼 수 있다.
- 회원은 저장한 매장을 다시 해제할 수 있다.
- 카카오 검색 결과로 노출된 장소라도 Toggle 내부 `store` 기준으로 안정적으로 저장할 수 있어야 한다.

## 4. Non-Goals
- 공공기관 즐겨찾기 정책 고도화
- 폴더형 즐겨찾기 분류
- 즐겨찾기 알림
- 즐겨찾기 공유
- 추천 알고리즘 반영

## 5. Target Users
- Guest: 즐겨찾기 버튼을 누를 수는 있으나 로그인 유도만 받는다.
- Member: 즐겨찾기 추가, 조회, 해제가 가능하다.
- Owner: 일반 회원과 동일한 개인 즐겨찾기 기능만 사용한다.
- Admin: 기능은 사용할 수 있으나 운영 기능의 일부는 아니다.

## 6. User Scenarios

### Scenario 1
- 사용자는 지도에서 현재 영업 중인 매장을 보고 나중에 다시 방문하고 싶어 하트를 누른다.
- 로그인된 상태라면 즉시 저장되고 저장 목록에서 확인할 수 있다.

### Scenario 2
- 비회원 사용자가 리스트에서 하트를 누른다.
- 서비스는 현재 탐색 흐름을 막지 않고 로그인 모달 또는 로그인 유도를 보여준다.

## 7. Functional Requirements

1. 로그인된 사용자는 매장에 대해 즐겨찾기 추가/해제를 할 수 있어야 한다.
2. 비로그인 사용자가 즐겨찾기를 시도하면 로그인 유도 UI를 보여줘야 한다.
3. 동일 사용자가 동일 매장을 중복 저장할 수 없어야 한다.
4. 사용자는 자신의 즐겨찾기 목록을 조회할 수 있어야 한다.
5. 즐겨찾기 상태는 카드, 리스트, 상세, 저장 목록에서 일관되게 보여야 한다.
6. 삭제되었거나 접근 불가능한 매장은 목록에서 안전하게 처리되어야 한다.
7. 카카오 장소 검색 결과를 즐겨찾기할 때는 외부 장소 식별자를 이용해 Toggle 내부 `store`로 매핑할 수 있어야 한다.

## 8. UX / Interaction Notes
- 즐겨찾기 진입점은 카드/상세/목록의 하트 버튼이다.
- 로그인 전에는 페이지 이동 강제보다 로그인 모달/유도 버튼이 우선이다.
- 저장 성공/해제 성공은 즉시 UI에 반영되어야 한다.
- 즐겨찾기 목록이 비어 있으면 빈 상태 화면을 제공해야 한다.

## 9. Domain Considerations
- 핵심 엔티티는 `users`, `stores`, `favorites`이다.
- `favorites`는 `(user_id, store_id)` 유니크가 필요하다.
- 즐겨찾기는 "현재 상태"가 아니라 사용자-매장 관계 데이터다.
- `stores`는 Toggle 서비스의 기준 엔티티이고, 카카오 장소 결과는 `external_source`, `external_place_id`로 매핑된다.
- 즐겨찾기는 카카오 장소 ID를 직접 저장하지 않고, 매핑된 `store.id`를 기준으로 저장한다.

## 10. Backend Considerations
- `POST /api/v1/favorites/stores/{storeId}`
- `DELETE /api/v1/favorites/stores/{storeId}`
- `GET /api/v1/favorites/stores`
- 필요 시 `POST /api/v1/stores/resolve` 또는 내부 resolve 로직으로 카카오 `placeId`를 `storeId`로 연결한다.
- 서비스 계층에서 로그인 사용자 본인 기준으로만 처리해야 한다.

## 11. Edge Cases
- 비로그인 사용자의 추가 요청
- 이미 즐겨찾기한 매장 재추가
- 존재하지 않는 매장 ID
- 카카오 검색 결과는 있으나 아직 Toggle `store`로 매핑되지 않은 장소
- 삭제되었거나 비활성 상태인 매장
- 빠른 연속 클릭으로 인한 중복 요청

## 12. Success Metrics
- 회원의 즐겨찾기 추가 성공률
- 즐겨찾기 목록 재방문율
- 비회원의 로그인 전환율

## 13. Open Questions
- 공공기관도 동일한 즐겨찾기 엔드포인트로 다룰지 별도 모델로 갈지
- 저장 목록에서 정렬 기준을 최신순으로 고정할지 선택 옵션을 둘지
- 카카오 장소가 우리 `stores`에 없을 때 자동 등록할지, 제한된 등록 정책을 둘지
