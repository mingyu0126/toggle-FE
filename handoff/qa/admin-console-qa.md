# Admin Console QA Report

## Scope
- 관리자 로그인 화면
- 관리자 신청 목록/상세/후보 조회 화면
- 관리자 승인/반려 액션 UI
- 관리자 권한 라우팅

## Findings And Fixes

### 1. `/admin`가 실제 관리자 콘솔이 아니라 예전 mock 화면으로 연결됨
- 문제: 모바일 경로 `/admin`이 실제 승인 콘솔이 아닌 레거시 mock 관리자 페이지를 열었다.
- 영향: 운영자가 환경에 따라 서로 다른 화면을 보게 되어 승인 흐름이 끊긴다.
- 조치: `/admin`을 `/adminweb` 실제 콘솔로 리다이렉트하도록 수정했다.
- 상태: fixed

### 2. 관리자 로그인 화면이 실제 인증 API와 연결되지 않음
- 문제: 관리자 로그인 화면이 더미 비밀번호 방식이었다.
- 영향: 실제 `ADMIN` 계정으로 운영 검증이 불가능했다.
- 조치: `/api/v1/auth/login` 기반 실제 인증으로 전환하고 `ADMIN` role 체크를 추가했다.
- 상태: fixed

### 3. 관리자 로그인 중 중복 제출 가능
- 문제: 로그인 요청 중에도 버튼을 계속 눌러 중복 제출이 가능했다.
- 영향: 중복 인증 요청과 상태 꼬임 가능성이 있었다.
- 조치: 제출 중 버튼 비활성화와 로딩 문구를 추가했다.
- 상태: fixed

### 4. 관리자 페이지가 후보 조회 실패와 후보 없음 상태를 구분하지 못함
- 문제: 카카오 매칭 후보 로드 실패와 실제 후보 없음이 같은 화면으로 보였다.
- 영향: 운영자가 매핑 실패를 잘못 해석할 수 있었다.
- 조치: 후보 로드 에러 메시지를 별도로 노출하고, 신청 전환 시 후보 상태를 초기화했다.
- 상태: fixed

### 5. 다른 신청으로 이동해도 반려 사유/에러 상태가 남아 있음
- 문제: 이전 신청에서 입력한 반려 사유와 액션 에러가 다음 신청에 그대로 남았다.
- 영향: 잘못된 신청에 반려 사유를 제출할 위험이 있었다.
- 조치: 선택한 신청이 바뀌면 반려 사유와 에러 상태를 초기화하도록 수정했다.
- 상태: fixed

### 6. 관리자 화면 탭 제목이 기본값으로 노출됨
- 문제: 브라우저 탭 제목이 기본값으로 남아 관리자 페이지 식별이 어려웠다.
- 영향: 다중 탭 운영 시 혼란이 생긴다.
- 조치: 관리자 로그인/콘솔에 명시적 document title을 추가했다.
- 상태: fixed

### 7. 관리자 로그인 입력 필드에 적절한 autocomplete 속성이 없음
- 문제: 이메일/비밀번호 입력에 브라우저 보조 속성이 부족했다.
- 영향: 비밀번호 매니저와 브라우저 자동완성 UX가 떨어졌다.
- 조치: `email`, `current-password` autocomplete를 추가했다.
- 상태: fixed

## Verification
- backend: `./gradlew test`
- frontend: `npm run build`
- browser: 관리자 로그인 화면, 콘솔 제목, 입력 보조 속성, 신청 상세 상태 초기화 흐름 확인

## Notes
- 개발 시드에 관리자 QA용 `PENDING` 신청 1건을 추가했다.
- 브라우저 자동화 도구에서는 로그인 버튼 클릭 후 라우팅 전환이 안정적으로 캡처되지 않아, API 응답과 빌드/테스트 검증을 함께 사용했다.
- 추가 조사 결과, 후보 조회가 `500`으로 실패할 때의 직접 원인은 카카오 앱 `toggle`에서 Local API 권한이 비활성화된 것이다. 카카오 응답은 `NotAuthorizedError` / `App(toggle) disabled OPEN_MAP_AND_LOCAL service.`였다.
- 개발 시드의 기존 `APPROVED` 신청들은 실제 매핑 서비스를 통과하지 않고 승인 상태만 저장되어 `mappingStatus=PENDING`으로 남아 있다. 운영 화면에서 이 값이 현재 링크 상태와 불일치할 수 있다.
- 승인 정책은 이후 변경되어, 현재는 "사업자 수동 확인 + 주소 자동 매핑 성공 + 실제 링크 생성 성공"이 모두 충족될 때만 승인할 수 있다.
- 이후 백엔드 계약이 한 번 더 바뀌어, 현재 관리자 콘솔은 `requestStatus`, `businessVerificationStatus`, `mapVerificationStatus`를 기준으로 동작한다.
- 관리자 콘솔에서 전국 주소 국세청 자동 재검증, 예외 상황 수동 보정, 카카오맵 재검증, 최종 승인/반려를 수행할 수 있게 연결했다.
- 추가 QA에서 아래 문제들을 수정했다.
  - 상세 패널이 액션 이후 최신 상태로 다시 로드되지 않아 승인/수동 검증 직후 stale 상태를 보여주던 문제
  - 상세 조회와 후보 조회를 `Promise.all`로 묶어서 후보 로딩 실패 시 상세 화면 전체가 사라지던 문제
  - 이미 `APPROVED` 된 신청에 대해 사업자 재검증/지도 재검증을 다시 실행할 수 있던 상태 무결성 문제
  - 이미 `REJECTED` 된 신청에 대해 수동 검증이나 자동 재검증을 다시 실행할 수 있던 상태 무결성 문제
  - 테스트 정리 순서가 FK 제약을 깨서 통합 테스트가 불안정하던 문제
  - `서울특별시`와 `서울`이 같은 주소인데도 정규화가 달라 카카오 후보 점수가 전부 `0/no-signal`로 계산되던 문제
  - `매장명 + 주소` 검색 결과가 조금이라도 있으면 더 정확한 `주소만 검색` fallback을 아예 시도하지 않던 문제
  - 국세청 API 미설정/외부 장애가 실제 사업자 불일치와 똑같이 `AUTO_VERIFICATION_FAILED`로 저장되던 문제
  - `forceRefresh=false` 요청인데도 지도 재검증이 항상 외부 API를 다시 호출하던 API 계약 불일치 문제
  - 상단 `새로고침`이 목록만 갱신하고 상세 패널은 그대로 둬서 좌측 목록과 우측 상세 상태가 서로 어긋나던 문제
  - 관리자 자동 검증/지도 재검증 액션이 감사 로그에 남지 않던 추적성 문제
  - 새 검증 엔드포인트에 레거시 `/owner-store-applications/...` alias가 빠져 하위호환성이 깨진 문제
  - 서울/비서울 분기를 전제로 한 관리자 화면 문구와 액션 구조가 실제 전국 자동 검증 정책과 어긋나던 문제
  - 카카오 조회 정책을 점주 입력 실영업주소 기준으로 다시 단순화하면서 도로명주소 변환 단계가 불필요해진 점
  - 실영업 전화번호를 프론트에서 받기로 했는데 백엔드 신청 모델/조회 응답/관리자 검색에서 이 값이 완전히 빠져 있던 문제
  - 같은 주소 후보가 많을 때 전화번호 신호를 전혀 쓰지 않아 전혀 다른 업장이 같은 점수로 보이던 후보 스코어링 문제
  - `매장명+주소`와 `주소` 검색 결과가 중복될 때 같은 place가 여러 번 노출될 수 있던 후보 중복 문제
  - 지도 검증을 아직 실행하지 않은 신청에도 실시간 후보를 먼저 보여줘 운영자가 이미 검증된 것으로 오해할 수 있던 문제
  - 지도 검증 실패 이력이 상세 화면에서 실패 사유 없이 시간만 보여 실패 원인을 파악하기 어려웠던 문제
  - 카카오 매칭이 여전히 후보/점수 개념에 기대고 있어 exact address only 정책을 깨뜨릴 수 있던 문제
  - 카카오 exact match 비교가 도로명주소 한 축만 보고 있어, 지번주소로 신청한 정상 매장을 놓칠 수 있던 문제
  - exact address 결과가 여러 건일 때 전화번호 하나만 맞으면 자동 확정하던 위험한 분기 문제
  - 관리자 정책과 어긋나는 `/match-candidates` API와 점수/후보 DTO가 남아 있어 운영 규칙을 잘못 학습시키던 문제
  - 승인 요청 body가 `businessVerified`라는 이름을 써서, 최종 승인 API가 검증 상태를 외부 입력으로 받는 것처럼 보이던 계약 문제
  - 전국 자동 검증 정책으로 바뀌었는데도 도메인에 `seoulAddress` 필드가 남아 있던 정책-모델 불일치 문제
  - 개발 시드 신청이 `PENDING/NOT_STARTED`로 떠서 관리자 첫 화면이 현재 검증 흐름을 잘못 보여주던 문제
  - 기존 dev seed 레코드가 남아 있으면 새 시드 보정 로직이 적용되지 않던 초기화 문제

## Recommended Next Step
- 카카오 개발자 콘솔에서 `OPEN_MAP_AND_LOCAL` 권한을 켠 뒤 후보 조회/승인 흐름을 다시 확인한다.
- 국세청 서비스키를 넣은 뒤 `AUTO_VERIFICATION_UNAVAILABLE -> AUTO_VERIFIED` 전환이 정상 동작하는지 확인한다.
- 브라우저에서 `admin@toggle.com / password123!`로 로그인한 뒤 `운영 확인용 토글 샵` 신청에 대해 사업자 자동 검증, 지도 재검증, 최종 승인까지 수동 확인한다.
- exact address가 여러 건일 때 자동 실패하는지 운영 데이터로 다시 확인한다.
- exact address가 0건 / 1건 / 여러 건인 세 케이스를 실제 카카오 결과로 다시 나눠 확인한다.
