## fail to fetch QA 라운드
- 사용자 보고 기준으로 화면에서 점주 운영정보 저장 시 `fail to fetch` 알림만 뜨는 현상을 다시 재현/분석했다.
- 로컬 서버 프로세스는 떠 있었지만, 새로 추가한 `PUT /api/v1/owner/stores/{storeId}/profile` 요청이 브라우저 preflight 단계에서 막힐 수 있는 구성이었다.

### 이번 라운드에서 잡은 문제
- 문제 1. `WebConfig`의 CORS 허용 메서드에 `PUT`, `PATCH`가 빠져 있어 profile 저장 요청 preflight가 실패할 수 있었다.
- 문제 2. `SecurityConfig`에서 `http.cors()`가 빠져 있어 Spring Security 체인에서 CORS 헤더가 누락될 수 있었다.
- 문제 3. `OPTIONS` preflight 요청을 명시 허용하지 않아 인증이 필요한 owner API 앞단에서 브라우저가 막힐 수 있었다.
- 문제 4. 프론트 `apiRequest`가 네트워크/CORS 실패를 그대로 `Failed to fetch`로만 노출해 원인 파악이 매우 어려웠다.
- 문제 5. 점주 이미지 저장 시 기본 placeholder 이미지까지 서버에 저장돼 실제 점주 사진 데이터가 오염될 수 있었다.
- 문제 6. 이미지 업로드 UI는 `최대 10장`이라고 쓰여 있지만 실제로는 제한이 없어 과도한 base64 payload를 쌓을 수 있었다.
- 문제 7. 점주 저장 버튼이 중복 클릭 가능해 같은 profile 저장 요청이 여러 번 동시에 날아갈 수 있었다.

### 조치
- 백엔드 CORS 허용 메서드에 `PUT`, `PATCH`를 추가했다.
- Spring Security에 `cors(Customizer.withDefaults())`와 `OPTIONS /** permitAll`을 추가했다.
- 프론트 `apiRequest`는 fetch 자체 실패 시 `서버 연결에 실패했습니다. 백엔드 실행 상태와 CORS 설정을 확인해 주세요.`로 안내하도록 바꿨다.
- 점주 profile 저장 payload는 기본 placeholder 이미지를 제외하고, 최대 10장까지만 서버에 전송하도록 정리했다.
- 모바일/웹 점주 페이지 저장 버튼에 `isSavingProfile` 보호를 넣어 중복 저장을 막았다.

  - **두 번째 클릭 (또는 강조 중인 카드 재클릭 시)**: 해당 장소 상세 페이지로 최종 이동한다.

### 사용자 UX 고도화 (현 지도 영역에서 검색하기 및 GPS 자동 활성화)
- 지도를 조금만 드래그해도 서버 API가 실시간으로 반복 호출되는 현상을 막고 사용자가 원할 때만 지도 결과 영역을 갱신할 수 있도록 리팩토링했다.
- **`searchCenter` 상태 분리**: 뷰포트를 나타내는 `mapCenter` 연동 로직과 장소를 검색해오는 기준이 되는 `searchCenter` 연동 로직을 분리했다. 이제 지도를 움직여도 뒷단 검색은 움직이지 않는다.
- **현 지도에서 검색 버튼 버그 수정 및 UX 개선**: 
  - 지도의 포커스(`mapCenter`)가 달라지면 화면 상단에 '현 지도에서 검색' 버튼이 나타난다. 하지만 이 버튼이 카카오 `<Map>` 컴포넌트 내부에 있어서 이벤트가 유실(intercept)되어 클릭이 먹히지 않는 버그가 있었다. 이를 해결하기 위해 HTML DOM 구조 상 **검색 버튼 컴포넌트를 완전히 `<Map>` 영역 외부의 상위 Relative 레이어로 분리**하여 해결했다. 추가로 호버/클릭 시 반응성을 주기 위한 인터랙션 CSS와 아이콘을 삽입했다.
- **토글 가맹점 프리미엄 마커 디자인 적용 (`CustomOverlayMap`)**:
  - 기본 카카오 장소 검색 결과와 **Toggle 서비스에 가입(등록)된 매장**을 시각적으로 강렬하게 분리하기 위해, 등록된 매장(`status !== 'UNREGISTERED'`)의 경우 기본 드롭 핀 마커를 사용하지 않도록 개편했다.
  - 카카오맵 API의 `<CustomOverlayMap>`을 활용해 CSS 커스텀 핀을 설계했다. Toggle의 프라이머리 컬러인 블루와 퍼플 계열의 화려한 `linear-gradient` 코팅, 부드러운 드롭 섀도우, 화이트 아우트라인, 그리고 매장 이름 글자가 즉시 표시되는 아주 고급스러운(Premium) 말풍선형 디자인 핀을 직접 그렸다. 이제 지도 상에서 토글 가맹점이 한눈에 엄청나게 돋보이게 되었다.
- **앱 시작 시 자동 현위치 매핑**: 앱 진입(`mount`) 시 기존의 강제 고정 하드코딩 위경도를 무시하고 단 한 번 `navigator.geolocation`을 자동으로 호출하여 실제 사용자의 접속 위치로 바로 맵이 초기화되도록 기본 처리 규약을 변경했다.

### 치명적 버그 수정 (상세페이지 무한 렌더링 및 상태 유실 개선)
- **`StoreWeb` 무한 렌더링 및 브라우저 크래시 해결**: `StoreWeb.jsx` 내 지도 중앙 좌표 동기화 `useEffect`가 새로운 객체 참조인 `[store]`를 의존성으로 가지고 있어 렌더링 ➡ 상태 업데이트 ➡ 재렌더링의 무한 루프(Maximum update depth exceeded)를 유발하던 치명적인 버그를 잡아냈다. 의존성을 `[store?.lat, store?.lng]` 원시값으로 변경하여 완벽하게 수평을 잡았다.
- **지도 말풍선 클릭 시 상태(State) 유실 방지**: `HomeWeb.jsx`의 검색결과 마커 위 스마트 핀 말풍선을 클릭해 상세페이지로 진입할 때 카카오에서 가져온 기반 데이터를 넘기지 않아 상세페이지가 멈추거나 뻗는 문제를 해결했다. `navigate` 옵션에 `state: { placePreview: originalData }`를 명시적으로 주입 완료했다.
- **`StoreWeb` 및 `PublicWeb` Empty State(에러 뷰) 전면 개편**: 주소창에 직접 URL을 입력하고 들어가서 `state`가 텅 비었을 때 까만 화면 중앙에 "장소를 찾을 수 없습니다" 텍스트 1줄만 렌더링되어 앱이 죽은 것처럼 보이던 현상을 고쳤다. 글로벌 헤더와 우측 빈 지도를 그대로 냅두고 중앙 우측 레이아웃에 경고 아이콘과 '지도로 돌아가기' 버튼을 포함한 아주 우아한 프리미엄 에러 스크린을 렌더링하도록 UI를 전면 보강했다.

### 프론트엔드 반응형 웹(Responsive Web) 및 인터랙션 수정 결산
- **데스크탑 웹 반응형(Media Query) 전면 도입**: `HomeWeb.module.css`, `StoreWeb.module.css`, `LandingWeb.module.css`, `ListWeb.module.css` 전역에 1024px(태블릿), 768px(모바일) 브레이크포인트를 적용하였다. 모바일 환경 진입 시 좌측 사이드바와 우측 지도가 상하 스택(Stack) 구조로 자연스럽게 배치되도록 아키텍처를 대대적으로 개선했다.
- **지도 드래그 Jittering(떨림) 문제 해결**: 이전에 부드러운 위치 이동을 위해 추가했던 `<Map isPanto={true}>` 옵션이 사용자의 드래그와 충돌해 지도가 제자리에서 진동하듯 떨리는 현상을 유발했으나, 해당 옵션을 완전히 제거하여 안정적인 드래그 홀드를 복구했다.
- **웹 환경 1-Step 목록 진입 로직**: 모바일 맵의 바텀시트는 '첫 클릭 시 핀 이동 ➡ 두 번째 클릭 시 상세 이동'의 2-Step 방식이지만, 사이드바 레이아웃이 넓게 확보된 데스크탑 웹 브라우저(`HomeWeb.jsx`)의 목록은 1회 클릭만으로 즉시 상세(StoreWeb)로 넘어가도록 `onClick` 덮어쓰기 로직을 해제하여 UX 정책을 분리했다.

## Main Agent 재라우팅 및 감사 로그 보강
- 서브에이전트 결과가 불완전하거나 충돌할 때 `Main Agent`가 `re-dispatch / upstream return / gate hold` 중 무엇을 해야 하는지 `.agents/workflows/main-agent-orchestration.md`와 `.agents/workflows/build-fullstack-feature.md`에 추가했다.
- `.agents/workflows/04-code-review.md`, `.agents/workflows/05-finish-branch.md`에도 `QA Reviewer`, `DevOps`를 실제 subagent로 dispatch하고 결과를 merge하는 런타임 프로토콜을 추가했다.
- `.agents/templates/subagent-audit-log-template.md`를 추가해 어떤 subagent를 왜 띄웠고, 무엇을 받아서 어떤 게이트 판단으로 이어졌는지 기록하는 표준 포맷을 만들었다.
- `docs/development-workflow.md`와 루트 `AGENTS.md`에 delegated work는 `daily-log`에 감사 가능한 라우팅 흔적을 남겨야 한다는 규칙을 추가했다.
