# 2026-04-14

## Main Agent 역할 축소 및 서브에이전트 기본 위임 규칙 강화
- 사용자 요청에 따라 `Main Agent`를 “직접 구현도 하는 총괄자”가 아니라, 기본적으로 판단하고 배분하는 오케스트레이터로 더 강하게 고정했다.
- `.agents/agents.md`에 `Main Agent`는 기본 implementer가 아니라 orchestrator라는 원칙을 추가했다.
- `.agents/workflows/main-agent-runtime-dispatch.md`에 specialist work는 실서브에이전트가 생산하고 `Main Agent`는 승인과 재라우팅을 맡는다는 기본 규칙을 강화했다.
- `docs/development-workflow.md`와 루트 `AGENTS.md`에도 “Main Agent는 결정하고 위임한다”는 운영 stance를 명시했다.
- 의미 있는 역할 작업을 Main Agent가 직접 처리하는 경우는 예외로 보고, 그 사유를 설명할 수 있어야 한다는 기준을 추가했다.
- 추가 재발 방지 규칙: `속도가 더 빠를 것 같다`, `컨텍스트 유지가 쉽다` 같은 이유만으로 Main Agent가 위임 기본을 깨면 안 되며, 예외 실행은 사전 선언 + 일일 로그 사유 기록이 필수다.

## 검증
- `.agents`, `docs`, `AGENTS.md`에서 `Main Agent`가 orchestrator이고 specialist subagent가 기본 실행 주체라는 문구가 일관되게 들어갔는지 검색으로 확인했다.

## 로그인 디버깅 및 라우팅 수정
- 사용자가 직접 프론트/백엔드 서버를 띄운 상태에서 로그인 실패를 재현하고, 브라우저 콘솔과 네트워크 로그를 함께 확인했다.
- `POST /api/v1/auth/login` 자체는 동작했지만, 데스크탑 점주 로그인 성공 후 `LoginWeb.jsx`가 `/posweb`이 아니라 모바일 경로인 `/pos`로 보내는 라우팅 불일치를 확인했다.
- 일반 로그인 폼에서 관리자 계정으로 시도할 때도 더 명확한 안내가 필요해, 일반 로그인과 데스크탑 로그인 모두 `ADMIN` 계정에 대해 전용 로그인 페이지 사용 메시지를 추가했다.
- 수정 대상:
  - `apps/frontend/src/pages/LoginWeb.jsx`
  - `apps/frontend/src/pages/Login.jsx`
